## ЗАМЫСЕЛ — читать первым, он определяет все решения ниже

Турнир должен работать как настоящая компания, а не как упражнение. Команды не знают параметров рынка: ни `a`, ни `b`, ни своих `c_i`. **Единственный способ их увидеть — оценить по данным.** Отсюда всё остальное: эконометрика здесь не домашка, приделанная к игре, а единственный путь к решению. Посчитал регрессию правильно — увидел спрос и выбрал объём почти оптимально. Посчитал не тем методом — получил смещённую оценку, поставил не тот объём и потерял прибыль, причём потерял видимо и объяснимо.

У каждого раунда уже есть `Round.method` из шести методов курса Кудрявцева. Метод раунда определяет, **какое искажение заложено в данные этого раунда**: в раунде по гетероскедастичности дисперсия ошибки обязана расти с объёмом, в раунде по автокорреляции остатки обязаны быть скоррелированы во времени, в раунде по мультиколлинеарности регрессоры обязаны быть скоррелированы между собой, в панельном раунде обязаны быть индивидуальные эффекты фирм. Если данные этого не содержат — метод превращается в театр, и вся конструкция рассыпается. Это самое важное требование во всём задании.

Интерфейс должен читаться как рабочее место аналитика: брифинг раунда, комната данных со скачиванием, отчёт аналитика с загрузкой файла, решение совета, дашборд с KPI. Не «страница 3 учебного приложения». Красиво, удобно, понятно с первого взгляда — это требование, а не пожелание.
