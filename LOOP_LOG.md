# LOOP_LOG

Журнал автономных итераций. Читается **в начале каждой итерации**, дописывается в конце.

Смысл файла один: не дать циклу заново открывать тот же тупик. Неудачная попытка
здесь ценнее удачной — удачу видно по `git log`, а неудачу больше нигде не видно,
и без записи она повторится на следующей итерации.

Формат строки — четыре поля, ничего лишнего:

```
## ГГГГ-ММ-ДД ЧЧ:ММ — <что взял>
Итог: получилось / не получилось / частично
Чем проверено: <команда и число прошедших тестов>
Заметка: <что именно мешало, если мешало; какой путь закрыт и почему>
```

Правила:
- Писать сразу после попытки, а не в конце сессии.
- «Не получилось» писать подробнее, чем «получилось».
- Если путь признан тупиковым — сказать это явным словом «тупик», чтобы следующая
  итерация могла найти его поиском по файлу.

## 2026-08-14 — фаза 0, пункт 1: round_shocks и effective_parameters

Итог: получилось.

Чем проверено: `uv run pytest -q` → **259 passed** (было 248, +11 — весь модуль
`test_round_service_events.py`). `ruff check services core db` → чисто.
`mypy services core` → чисто. Коммит `feat: wire market events into round scoring`,
запушено на master.

Заметка: писать почти ничего не пришлось — весь расчёт уже лежал в
`core/market_events.py` (`apply_to_parameters`, `apply_to_demand`, `apply_to_costs`),
включая нужный тексту теста оборот «нежизнеспособным». Не хватало только слоя
перевода из БД в движок. Три вещи, которые важно не сломать при последующих правках:

1. **`revealed` не доезжает до движка намеренно.** Флаг управляет показом события
   командам до подачи решения, а не расчётом. Скрытый шок двигает рынок так же,
   как публичный. Тест `test_hidden_event_still_moves_the_market`.
2. **`Round` не мутируется.** Базовые `market_a`/`market_b`/`market_mc` остаются в
   БД нетронутыми, иначе после раунда нельзя отделить «тебя двинуло событие» от
   «тебя двинуло собственное решение». Тест `test_base_round_parameters_stay_untouched`.
3. **В асимметричной ветке издержки проверяются против уже сдвинутой точки
   насыщения**, а не против исходной — то есть против того рынка, на котором раунд
   и будет считаться.

Регрессия «без событий считается байт-в-байт как раньше» держится на том, что
множители при пустом наборе шоков равны ровно `1.0`, а умножение на `1.0` точное.
Если кто-то заменит свёртку на что-то вроде `sum(magnitudes)`, эти два теста
покраснеют первыми — так и задумано.
