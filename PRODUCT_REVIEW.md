Проход по двум путям — преподавателя и студента — глазами продукт-инженера,
после чего 12 итераций по протоколу `LOOP_PROMPT.md`. Здесь: что есть

`LOOP_LOG.md`, записи от 12.09.

Состояние: **482 зелёных теста**, `ruff`/`mypy` чисто, 13 коммитов за день,
всё на `master`. Полный путь пройден на чистой базе с реальным Groq.

## 1. Путь Кудрявцева — как он мониторит

```
seed → пароль → Новый раунд (метод, a/b/c, предпросмотр Нэша, предупреждения)
     → команды считают → Закрыть раунд → результаты (деньги)
     → Панель разбора (оценка раунда, кто попался, во что верил)
     → Микрозащита (кнопка: команда × роль × вопрос + ожидаемый ответ)
     → Оценить обоснования (Groq, рубрика метода с истиной раунда)
     → История раундов, накопленная прибыль
```

Что он видит и чего не видел утром:

| Экран | Утром 12.09 | Вечером 12.09 |
|---|---|---|
| Форма раунда | только парная регрессия, `a/b/c` вслепую | 3 метода; Нэш при текущем числе команд; предупреждения «повтор параметров», «тесный рынок» |
| Замок | нет — студент со ссылкой видел `a/b/c` и разбор | `DASHBOARD_PASSWORD`; витрина открыта |
| После закрытия | таблица прибылей | + панель разбора: оценка раунда, `Q сдано / наивный / верный`, вердикт, ожидаемая цена |
| Капканы | ловушка в данных | + микрозащита, + рубрики на 3 метода с проверкой чисел |
| Второй раунд | можно открыть поверх открытого — бот слал решения не туда | отклоняется до записи |
| Демо | пустой экран | `uv run python -m devshell.demo_round` |

## 2. Путь студента — чтобы было интересно

```
/join <код> → /brief (рынок, сюжет, задача, ВАША ФИРМА: издержки, число фирм)
           → /data (CSV + словарь файлами) → считает → /submit Q обоснование
           → раунд закрыт → /result: «вы ждали цену 42, рынок дал 21;
             лучший ответ Q=11, недобор 436; оценка 46 %, место 7 из 7»
```

Утром студент не мог решить задачу вообще — брифинг обещал «издержки даны
отдельно», а отдельно их не давал никто. И не мог получить данные без ссылки
на витрину. И после закрытия узнавал только число в таблице.

Что делает игру интересной, а не «упражнением»: цена ошибки приходит в личку
числом через минуту после закрытия, в терминах «во что вы верили» — не
«вы проиграли», а «вы ставили на 42, рынок дал 21, вот чего стоил незамеченный
сдвиг». Это `core/beliefs` + `/result`.

## 3. Капканы против «скинул CSV в чат» — три слоя

Ничего не запрещаем и «текст робота» не ловим (решение 08.09). Делаем так,
чтобы общий ответ стоил денег, баллов и лица.

1. **Ловушка в данных** (`core/cases`). Режимный сдвиг: сквозной МНК даёт
   наклон ровно 0.35·b и заниженную точку насыщения → перепроизводство в
   1.7×. Проверено на настоящих данных: 3/4/7 фирм × 5 зёрен.
2. **Рубрика, которая требует чисел** (`core/rubrics`). Каждый критерий —
   число из данных, ловушка с направлением ошибки, или связь оценки с
   объёмом. Грейдер получает истину раунда и наивную оценку — названное число
   проверяется. **Реальный Groq: генерик «оценили МНК, выбрали оптимальный
   объём» — 0.00 по всем пяти критериям; обоснование с числами — 1.00.**
3. **Устная микрозащита** (`core/defence`). После раунда — команда × роль ×
   вопрос про ловушку метода, розыгрыш детерминирован, ожидаемый ответ
   только преподавателю. Модель пишет обоснование; через десять секунд
   после жеребьёвки отвечает человек.

Плюс детектор «кто попался» — по объёму против наивной и верной процедуры на
тех же данных, с ожиданием соперников из истории. Несколько наивных команд
друг друга не прячут.

## 4. Находка дня — сырая прибыль награждает того, кто попался

Честная наивная команда на широком рынке (`300/1/30`, 7 команд): объём 58.5
против Нэша 33.75, **прибыль 528 против 305 у каждой из шести верных**.
Единственный перепроизводитель в Курно — лидер Штакельберга: сам теряет 611
против своего лучшего ответа, но остальные из-за него теряют по 834. По
деньгам он первый. Утром это никто не видел, потому что детектор по `b̂`
его не ловил (неявный наклон 0.58·b, а не 0.35·b — заниженный интерсепт
компенсирует).

Принято по числам, обратимо: **оценка раунда = доля от прибыли лучшего
ответа** (`br_share`), панель и `/result` — по ней. Деньги остаются деньгами
в `Result.profit` и накопленном итоге. Тест фиксирует факт, чтобы правило не
упростили обратно.

## 6. Что решать Саше — не ассистенту

- **Накопленный лидерборд**: деньги или доля (п. 5.1). Рекомендация — доля
  для оценки, деньги как бюджет механик №2/№6, если они будут; то есть два
  числа, а не одно.
- **Порядок оставшихся кейсов** под реальный план семестра Кудрявцева: сколько
  раундов и в каком порядке темы. Без этого три кейса могут оказаться лишними.
- **Дата демо.** Всё блокирующее закрыто. Ничего из п. 5 демо не держит.

## 7. Чему это учит (prototype-mode)

- **Прогон ловит то, что тесты не видят.** Двойной открытый раунд, снятая
  модель Groq, 429 без backoff, наивная команда-победитель — все четыре
  найдены живым прогоном на чистой базе, ни один — 480 тестами. Тесты
  проверяют инварианты, которые ты уже знаешь; прогон — те, о которых не
  подумал.
- **«Наивная» команда должна быть честной.** Утренний сценарий с истинным
  интерсептом и наивным наклоном был худшим случаем, которого студент не
  получит; честный сквозной МНК дал другую картину и перевернул правило
  оценки.
- **Курно наказывает соседей, не грешника.** Внешний эффект перепроизводства
  ложится на тех, кто считал верно. Любая оценка «по деньгам за раунд» в
  олигополии награждает агрессию — это не баг турнира, это теория игр.
